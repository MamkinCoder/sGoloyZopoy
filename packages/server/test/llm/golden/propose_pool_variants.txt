# Задача: предложить новые варианты резюме для пула на hh.ru

Соискатель держит несколько резюме на hh.ru под разные направления. Предложи до 2 новых вариантов, которых ещё нет: другое направление или другой акцент внутри направления.

## Правила (обязательны для любого текста)

Ты пишешь от имени реального соискателя. Факты о нём только из `profile` и данных в этом промпте. Ничего не выдумывай.

Правдивость:
- Заявляй только навыки и опыт из `profile.verified_skills`, `profile.summary` и переданного резюме.
- НИКОГДА не упоминай как свой опыт: Kubernetes, Kafka, RabbitMQ, ClickHouse. Даже если вакансия требует. Если навык нужен, а его нет - молчи о нём или честно скажи, что в продакшене не использовал.
- Числа, даты, компании, должности - только из промпта. Зарплату называй только из `profile.salary_from`/`salary_to`; если там 0 - цифру не называй.

Стиль писем и ответов (по-русски, если вакансия не на английском):
- Живо, тепло и с энергией, но коротко и по делу. Можно «Привет!» и восклицательные знаки.
- Без лести компании. Без слов «инновационный», «динамичный», «синергия», «комплексный», «уникальный», «амбициозный».
- Без ИИ-штампов: никаких противопоставлений «не X, а Y», «X, а не Y», «не только X, но и Y», никаких «возможно/наверное/пожалуй», никаких тире (—) - только дефис с пробелами ( - ). Без списков, без эмодзи, без markdown.
- Никаких ссылок, email и телефонов в тексте письма (спам-фильтр hh.ru).
- 2-3 конкретных совпадения между вакансией и реальным опытом соискателя. Больше ничего.
- Не подписывайся именем, если промпт не просит.

Формат ответа: только JSON по схеме ниже. Без текста до и после, без ```-ограждений.

## Как собирать резюме под вакансию

Разбор вакансии:
- Обязательное: раздел «Требования» / «Мы ждём», слова «обязательно», «опыт от», и всё, что повторяется 2+ раза. Желательное: «будет плюсом», «приветствуется», упомянутое один раз.
- Выпиши ключевые слова: язык, фреймворки, БД, инфраструктура, домен. Главный стек - то, что в названии вакансии и в первых строках требований.

Адаптация (переупаковка, не сочинение):
- Бери только то, что есть в `profile.verified_skills`, `profile.summary` и исходном резюме. Нет в фактах - не пишешь, даже если вакансия требует.
- Для навыков, которые у соискателя реально есть, используй формулировку вакансии: «PostgreSQL», а не «реляционные БД»; «REST API», если вакансия пишет так.
- Релевантное вакансии - первым: в навыках, в «О себе», в порядке буллетов внутри места работы. Нерелевантное - ниже или убрать.
- Не менять смысл: «участвовал» не становится «руководил», должности и сроки как в источнике.

Техническое резюме и ATS/поиск hh.ru:
- Навыки - простыми ключевыми словами в написании вакансии (Go, TypeScript, Node.js, PostgreSQL, Docker). Без оценок уровня и синонимов подряд.
- Название должности - как вакансии на hh.ru: «Go-разработчик», «Backend-разработчик (Node.js)». Без Senior/Lead/Ведущий, если их нет в фактах.
- Стандартные разделы: «О себе», «Навыки», «Опыт работы», «Образование».
- Ключевые навыки: 8-15 штук, самые нужные вакансии первыми. Главный термин - 2-3 раза на всё резюме (о себе, навыки, буллет), не чаще.
- «О себе»: роль + годы опыта из фактов + главный стек + домен. Без общих слов «ответственный, коммуникабельный».

Буллеты:
- Формула: глагол действия + что сделал + результат или масштаб + конкретная технология. «Разработал сервис биллинга на Go с PostgreSQL и Redis, ...».
- Сильные глаголы: разработал, спроектировал, перевёл, оптимизировал, автоматизировал, интегрировал. Без «занимался», «помогал», «отвечал за».
- Числа (нагрузка, пользователи, проценты, сроки) - только если они есть в исходном резюме или профиле. Не придумывай и не округляй вверх. Нет числа - покажи масштаб словами из фактов.
- Одна-две строки на буллет, один факт на буллет.

Когда резюме подходит плохо:
- Название и направление резюме не совпадают с вакансией (react против go-backend).
- В его навыках нет главного стека вакансии, хотя в `verified_skills` он есть.
- Обязательные требования вакансии, которые соискатель закрывает, в резюме не видны.
Если главного стека нет и в `verified_skills` - адаптация не поможет, это несовпадение вакансии.

## Требования к варианту

- `title` - в стиле hh.ru (см. выше), например «Fullstack-разработчик (React, Node.js)». Без Junior тоже. Названия не должны повторять существующие и друг друга.
- `direction` - одно из `profile.directions`.
- `about` - 3-5 предложений «О себе» для этого направления из фактов `profile.summary`. Без ссылок и списков.
- `key_skills` - 8-15 навыков только из `profile.verified_skills`, самые релевантные направлению первыми.
- `based_on_resume_id` - hh id резюме из пула, которое ближе всего по направлению (для копирования), или "" если пул пуст.
- Разные варианты - разный акцент: язык, роль (backend / fullstack / frontend), домен из summary. Не плоди почти одинаковые.

## Схема ответа

```json
[
  {
    "title": string,
    "about": string,
    "key_skills": string[],
    "based_on_resume_id": string,
    "direction": string
  }
]
```

Верни только JSON.
