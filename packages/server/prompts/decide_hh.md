## Как решать

Цель соискателя - собеседования. Сначала определи тип соискателя по `profile` (`extra.target_role`, `hh_queries`, `directions`, `summary`): разработчик (пишет код) или нет (менеджер проектов / операций, аналитик, поддержка, маркетинг и т.п.).

**Разработчик.** Любая техническая роль рядом с его стеком подходит: backend, frontend, fullstack, DevOps, SRE, platform / infra, data engineering, ML / AI engineering, QA automation с кодом. Senior, «Старший» и «Ведущий разработчик» (в крупных компаниях это грейд senior, не руководитель) - откликайся, если `profile.experience` это допускает.
Отказ (`apply: false`) только если хотя бы одно:
- Lead / Head / Architect / Тимлид / руководитель, или явно требуют 7+ лет опыта.
- Основной стек вакансии совсем не пересекается с `verified_skills` (например только 1C, PHP/Bitrix, C++, .NET, Java-only, мобильная нативка без React Native).
- Это не техническая роль: продажи, менеджер без разработки, дизайн, поддержка первой линии, бизнес-аналитик без кода.
- Требуют навык из списка «никогда не заявлять» как ключевой и единственный.

**Не разработчик** (например менеджер проектов или операций). Подходит роль, которую он ищет (`target_role`, `hh_queries`) и смежные: project / delivery / operations / product manager, руководитель проектов, координатор, «Руководитель направления» уровня его опыта, в IT и digital, а также в других отраслях, если задачи те же. «Проектный менеджер», «Руководитель проекта», «Lead» в названии не причина отказа, если задачи ему по силам.
Отказ (`apply: false`) только если хотя бы одно:
- Роль, где главное - писать код или админить инфраструктуру (разработчик, DevOps, QA-автоматизация, системный аналитик с SQL/кодом), либо узкая отраслевая экспертиза, которой нет в профиле (1С, строительство, бухгалтерия, юрист и т.п.).
- Уровень явно выше: Head / Director / CxO / «директор по …», или требуют заметно больше лет опыта, чем в `profile.experience`.
- Продажи, холодные звонки, дизайн, первая линия поддержки, ассистент без управленческих задач.
- Требуют навык из списка «никогда не заявлять» как ключевой и единственный.

Иначе `apply: true`. Сомневаешься - откликайся, соискателю нужен объём откликов.
Резюме: то, у которого `direction` и `key_skills` больше всего пересекаются с вакансией.
`missing_skills` - только при `apply: false`: если роль, уровень и формат вакансии подходят, а отказ только из-за 1-3 конкретных навыков, которых нет в `verified_skills` и которые соискатель мог иметь (инструмент, технология, предметная область), перечисли их коротко («Java», «SQL», «Jira»). Тогда соискателя спросят, есть ли у него опыт. Если причина в роли, уровне, стеке целиком или навык из списка «никогда не заявлять» - пустой массив.
`direction` - направление вакансии одним словом из списка направлений профиля (например go-backend, react, fullstack, project-management, operations) или ближайшее.
`seniority` - junior / middle / senior / lead по тексту вакансии.
`red_flags` - короткие пометки: «тест», «5+ лет», «нужен Kubernetes», «зарплата ниже вилки» и т.п. Пустой массив, если нет.
`reason` - одно предложение, почему такое решение.
`fit_score` - 0-100, насколько вакансия совпадает с `verified_skills`, вилкой и форматом работы профиля (для любого `apply`). Честно: 80+ только при совпадении главного стека.
`fit_reason` - до 90 символов, конкретное пересечение или разрыв, например «Go+K8s, вилка ок, офис Москва». Только факты из профиля и вакансии.

Соответствие резюме (`resume_fit`), только если `apply: true`:
- `"good"` - только если `direction` выбранного резюме совпадает с `direction` вакансии И в названии резюме есть главная специализация вакансии (например «Go-разработчик» для Go-вакансии, «Руководитель проектов» для вакансии менеджера проектов).
- `"poor"` - во всех остальных случаях, например вакансия go-backend, а в пуле только fullstack-резюме, или название резюме не про главную специализацию вакансии. Тогда обязательно заполни `tailored` - резюме под эту вакансию:
  - `title` - желаемая должность в стиле hh.ru, без Senior / Lead / Ведущий / Тимлид.
  - `about` - 3-5 предложений «О себе» только из фактов профиля и базы знаний, без ссылок и контактов.
  - `key_skills` - 8-15 навыков ТОЛЬКО из `profile.verified_skills`, сначала те, что есть в вакансии.
- При `"good"` или `apply: false` поле `tailored` не нужно.

Массив, ровно один объект на каждую вакансию, в том же порядке:

## Схема ответа

```json
[
  {
    "vacancy_id": number,          // id вакансии из списка
    "apply": boolean,
    "reason": string,              // одно предложение
    "resume_id": string,           // hh id резюме из пула, "" если apply=false
    "cover_letter": string,        // 3-6 предложений или ""
    "direction": string,
    "seniority": string,           // junior | middle | senior | lead
    "red_flags": string[],
    "missing_skills": string[],    // только при apply=false, иначе []
    "resume_fit": string,          // good | poor
    "fit_score": number,           // 0-100
    "fit_reason": string,          // до 90 символов
    "tailored": {                  // только при resume_fit=poor, иначе не указывай
      "title": string,
      "about": string,
      "key_skills": string[]
    }
  }
]
```

Верни только JSON.
