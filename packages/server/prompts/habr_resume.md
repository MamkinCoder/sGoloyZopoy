# Задача: универсальный профиль соискателя на Хабр Карьере

На Хабр Карьере у соискателя ОДИН профиль (резюме), и бот откликается им на все вакансии подряд: Go / Node.js / Python backend, React / Vue / Next.js frontend, fullstack, AI / LLM / RAG, DevOps. Поэтому профиль должен быть универсальным и очень насыщенным: работодатель из любого из этих направлений должен сразу увидеть свой стек. Всё только из фактов ниже.

{{> _rules}}

- «О себе» и описания опыта - несколько абзацев, переносы строк разрешены. Списки через «- » внутри описания опыта разрешены. Тон спокойный и деловой, без «Привет!».
- Ссылок, email, телефонов нет нигде.

## Что вернуть

- `title` - заголовок резюме до 80 символов, широкий, например «Fullstack-разработчик: Go, Node.js, Python, React, AI/LLM». Без Senior / Lead, если их нет в фактах.
- `specializations` - 1-2 id из списка выше, самые широкие для этого стека (например фулстек и бэкенд).
- `qualification` - одно из Junior / Middle / Senior. Senior только если факты это прямо поддерживают; иначе Middle.
- `about` - «О себе», 4-6 абзацев через пустую строку: кто он и сколько лет опыта (фраза `profile.experience`), backend (Go, Node.js/TypeScript, Python; PostgreSQL, Redis, очереди), frontend (React, Vue, Next.js, SSR), AI/LLM (RAG, агенты, эмбеддинги, реальные проекты из `profile.extra`), инфраструктура и DevOps (Docker, CI/CD, Linux, мониторинг), формат работы (`profile.extra.work_location`, релокация). Конкретика и технологии, без общих слов про характер.
- `skills` - 25-30 навыков, самые востребованные первыми (Go, TypeScript, Node.js, Python, React, PostgreSQL, Redis, Docker ...). Только из `profile.verified_skills` и стека базовых резюме. Названия в общепринятом написании (Golang, Node.js, PostgreSQL, Vue.js, Next.js).
- `experiences` - по одному объекту на каждое место работы из «Что сейчас в профиле на Хабре», `company` дословно как там. `description` - 2-3 предложения обязанностей, затем 4-8 достижений строками «- ...» по формуле буллетов, затем строка «Технологии: ...». Для каждого места бери факты этого места из базовых резюме (одно и то же место может называться чуть по-разному: подразделение, сокращение, опечатка - сопоставляй по сходству названия и периоду) и из его текущего описания. Места, которого нет в базовых резюме, переписывай только из его текущего описания. Не добавляй мест работы и не меняй сроки.
- `notes` - короткие пометки для соискателя: что намеренно не включено и почему, что проверить руками.

Схема ответа - в конце промпта.
